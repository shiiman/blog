## はじめに

個人開発でバケットリストアプリ **Bucket List Commit** を作りました。iOS と Android の両方をひとりで書いて、両ストアに同時提出したところです。

この記事は**何を作ったか**の記録です。動機、画面、機能、規模を並べます。技術的な中身と、実装で踏んだ罠は別記事に分けました。

>

> シリーズ「アプリの中身と実装」全 12 本の 1 本目です。ストアに出すまでの手続きは[別シリーズ](/engineering/app/personal-app-cross-store-release-full-journey/)にまとめました。

---

## 何のアプリか

「やりたいことリスト」を書きためて、達成したら記録していくアプリです。キャッチコピーは「やりたいことを、一生のリストに」にしました。

名前の `Commit` は目標への決意という意味が主で、Git のコミットが副です。データを GitHub に持てるのが特徴のひとつなので、そこは意図した二重の意味にしています。

## なぜ作ったか

自分がこの手のアプリを長く使っていて、どれも「しっくりこなかった」のが動機です。テキストファイルから始めて既製アプリに移り、複数のアプリを試しても定着しませんでした。

不満は 6 つに整理できました。作るものは、その 6 つと 1 対 1 で対応させました。

| 不満 | どうしたか |
|---|---|
| UI が分かりにくい | ミニマルで応答性の高い UI にする |
| データやアカウントの連携が弱い | エクスポート / 端末間同期 / 外部連携を一級で持つ |
| 入力項目が多くて追加が面倒 | タイトルだけで登録できる Quick Add を主動線にする |
| 他のユーザーの内容が分からない | 公開リストとフレンドのリストを見られるようにする |
| モチベーションを支える仕組みがない | 達成を讃える演出といいねを入れる |
| カレンダーと連携できない | 達成を Google カレンダーへ自動で書き出す |

判断に迷ったときの軸は「自分が使い続けたいか」に決めました。マス向けの訴求と自分の使い心地がぶつかる場面では、自分の使い心地を優先しています。**自分が毎日使うことを前提に作る**という方針です。

### 差別化として研いだ 3 つ

競合を調べたうえで、この 3 つに力を入れると決めました。

1. **「夢」を「予定」に変える** — Google カレンダー連携を中心に据えて、「いつかやる」を「いつやる」に変換する。バケットリスト専用アプリでこれをやっているものが見つかりませんでした
2. **他人のリストからワンタップで取り込める** — 公開リストとフレンドのリストの両方から、項目ごと自分のリストへコピーできる。「何を書けばいいか分からない」で離脱するのを防ぎたかった
3. **データを自分の GitHub に置ける** — 各項目を GitHub の Issue + Projects v2 にミラーして、アプリと GitHub のどちらからでも編集できる。リストが「アプリの中のデータ」ではなく「自分のリポジトリにあるもの」になる

3 つ目は個人開発だからできた選択だと思っています。マス向けには刺さらない機能ですが、自分が一番欲しかったものでした。

## 画面構成

5 タブ + 全タブ共通の追加ボタンです。

```
起動 → オンボーディング（3〜4 ページ）
  └→ サインインせずにそのまま使える（ローカルのみモード）

タブバー
  1. ホーム    今日のリマインド / 期限が近い / 最近の達成 / 通知
  2. リスト    フィルタ・検索・並び替え → バケット詳細（= 編集画面）
  3. 追加      Quick Add モーダル（全タブから開く中央のボタン）
  4. 探す      定番バケット / 公開リスト / ランキング
  5. フレンド   ユーザー検索 / フレンドのリスト / 申請管理
  6. 設定      アカウント / 連携 / テーマ / 通知 / データ / このアプリについて
```

主な画面はこれだけあります。

| 画面 | 役割 |
|---|---|
| オンボーディング | 3〜4 ページ。最後に規約同意。初回はスターターバケットのピッカーも出る |
| ホーム | 期限が近いもの・最近の達成・アプリ内通知の入口 |
| リスト | 絞り込み / 検索 / 並び替え。iPad では 2 ペイン |
| Quick Add | タイトル必須、あとは任意。ここが主動線 |
| バケット詳細 | 編集画面と一体。チェックリスト・画像・メモ・いいね・共有 |
| 達成演出 | 3 秒の紙吹雪。音は鳴らさない |
| 探す | 定番バケット（サインイン不要）+ 公開リスト + ランキング |
| フレンド | 検索 / QR / 招待リンク。フレンド管理は 3 サブタブ |
| 統計 | 期間フィルタ + 達成率・推移・カテゴリ別。一部は Pro 限定 |
| 設定 | 8 セクション。連携は「身元」と「機能ごとのトークン」の 2 段構造 |
| ペイウォール | Pro の案内。自動更新の開示と規約リンクを載せる |
| GitHub 同期設定 | リポジトリと Projects の選択・同期履歴・手動再同期 |
| ブロック管理 | ブロックしたユーザーの一覧と解除 |

iPad はリスト・設定・フレンド・探すの 4 タブで 2 ペイン表示にしました。ホームはダッシュボードなので全幅のままです。横向きは iPad だけ対応で、iPhone は縦専用です。

## 機能一覧

| 分類 | 機能 |
|---|---|
| リスト管理 | CRUD / カテゴリ（14 固定 + ユーザー定義）/ チェックリスト / 画像 / メモの Markdown / 期限 / 場所 / 関連 URL |
| Quick Add | タイトルだけで登録。ショートカット App / Spotlight / ウィジェットからも起動 |
| GitHub 同期 | Issue + Projects v2 への双方向同期。操作時プッシュ + 起動時プル |
| 統計 | 達成率 / 推移 / カテゴリ別 / 期間フィルタ。詳細は Pro 限定 |
| テーマ | 基本テーマ + プレミアムテーマ 6 種（買い切り） |
| 公開範囲 | 非公開 / フレンド限定 / 公開の 3 段階 |
| 探す | 定番バケット / 公開リスト / ランキング / ワンタップ取り込み |
| フレンド | 検索・QR・招待リンク / 相互承認 / いいね / ブロック / 報告 |
| 共有バケット | 複数人で 1 つのバケットを共同編集 |
| 端末間同期 | iCloud（iOS のみ）。Android はバックアップと相互移行で代替 |
| 通知 | アプリ内通知 / ローカル通知（期限・思い出の今日・放置）/ 運営アナウンス |
| Google 連携 | カレンダーへの達成記録の自動書き出し / スプレッドシートへの統計出力（Pro 限定） |
| エクスポート | CSV / Markdown / PDF / Google スプレッドシート |
| ウィジェット | 進捗と近日達成。Quick Add の入口も兼ねる |
| ローカルのみモード | サインインせずに全ローカル機能が使える |

## プラン

|  | Free | Pro |
|---|---|---|
| バケット | 20 件 | 1,000 件 |
| フレンド | 2 人 | 50 人 |
| 1 件あたりの画像 | 1 枚 | 3 枚 |
| 詳細な統計 | — | あり |
| スプレッドシート出力 | — | あり |

Pro は月 ¥280 / 年 ¥2,800 です。買い切りプランは作りませんでした。

**プレミアムテーマは Pro に含めず、1 つ ¥250 の買い切りにしました**（6 種）。Pro に含めるとテーマだけ欲しい人が月額を払うことになり、逆に月額を払っている人が「テーマも入っているはず」と誤解します。役割が違うものは分けたほうが説明が短くなると考えました。

広告は入れていません。無料トライアルも作っていません。

## 開発期間と規模

コードを書き始めてから両ストアに提出するまで、**約 4 か月**でした。ひとりで、iOS と Android の両方です。

コミット数の月ごとの推移がこうでした。

| 経過 | コミット数 |
|---|---|
| 1 か月目 | 734 |
| 2 か月目 | 1,744 |
| 3 か月目 | 613 |
| 4 か月目 | 492 |
| 合計 | **3,585** |

2 か月目が突出しているのは、この時期に Android 版をまとめて書いたからです。iOS を先に作り切ってから移植したので、仕様の判断が済んでいて手が止まらなかった分です。

3 か月目以降が減っているのは、リリース前の検証と、コードの外側の作業（契約・税務・ストア登録・審査対応）に時間が移ったからです。**実装が終わってからストアに出すまでに 3 週間かかっています**（この話は[全工程まとめ](/engineering/app/personal-app-cross-store-release-full-journey/)に書きました）。

コードの量はこうなりました。

|  | ファイル | 行数 |
|---|---|---|
| iOS 本体 | 428 | 73,419 |
| iOS テスト | 282 | 39,462 |
| Android 本体 | 543 | 85,384 |
| Android テスト | 366 | 48,455 |
| 合計 | **1,619** | **246,720** |

**Android のほうが行数が多い**のは、SwiftUI に比べて Compose が明示的な記述を求める部分（状態のホイスティング、ViewModel、Flow の組み立て）と、iOS が標準で持っている機能を手で書いた部分（Markdown の整形、ネットワーク層）があるためです。

テストが全体の 36% を占めています。ひとりで両 OS を触ると、片方を直したときにもう片方が壊れているかどうかを目で確認できないので、テストがないと進めませんでした。

issue と PR の通し番号は **2,189 まで**進みました。1 つの機能を 1 つの issue にして、対応する PR を 1 本ずつ出す運用です。

## 実装しないと決めたこと

作らないと決めたものを最初に列挙して、以降ぶれないようにしました。**やらないことを決めておくと、途中で判断に迷う回数が減ります。**

| 決定 | 理由 |
|---|---|
| AI 機能（自動提案・自動生成） | 「自分のやりたいこと」を他人に決められたくないアプリなので |
| プッシュ通知（いいね・フレンド申請） | 落ち着いた体験を優先。アプリ内通知だけにした |
| コメント機能 | いいねだけにした。運用（モデレーション）を個人で背負えない |
| アプリ内の言語切り替え UI | OS の言語に従う設計にした（英語対応そのものは実装済み） |
| ストリーク（連続記録） | 生涯の目標を扱うアプリで毎日の連続を煽りたくなかった |
| 達成バッジ（1/5/10 件…） | 達成日・進捗グラフ・絞り込みで代替できると判断して途中で削除した |
| Apple Watch アプリ | 手首で見る価値のある情報が思いつかなかった |
| Mac Catalyst / Web 版 | 工数に見合わない |
| 買い切りプラン | サブスクだけにした |
| 無料トライアル | Free で主要機能が使えるので不要と判断 |
| アプリ内ブラウザ | 埋め込みブラウザを持つと年齢レーティングが上がるため、外部リンクは OS のブラウザへ渡す |
| SNS シェア用の達成カード画像 | 見栄えの作り込みに終わりがないので、リスト全体のシェアだけにした |
| GitHub 上のデータの暗号化 | 平文の Markdown であることがポータビリティの価値なので暗号化しない |

このうち **達成バッジは一度作ってから削除しました**。作ってみると、達成日と進捗グラフと「達成済み」の絞り込みで同じ役割が果たせていて、バッジは画面を賑やかにしているだけでした。

逆に、**当初やらないと決めていたのに後から追加したもの**もあります。

| 追加したもの | 理由 |
|---|---|
| ローカル通知（期限・思い出の今日・放置の掘り起こし） | プッシュを持たない代わりに、完全オプトインで静かな再訪導線を作った |
| 報告・ブロック・規約同意 | **両ストアの UGC ポリシーで必須**だったため。審査の途中で発覚した |
| Android 版 | 当初は iOS のみの予定だった。クロスプラットフォームの相互移行まで作った |

報告・ブロックは[ストア審査の必須要件](/engineering/app/personal-app-cross-store-release-full-journey/)として後から降ってきた分です。**ストアのポリシーは、実装内容に対する要件を後から追加してきます。**

## まとめ

作ってみて、順序について 3 つ思うところがありました。

1. **不満を先に列挙して、機能と 1 対 1 で対応させたのが効きました。** 迷ったときに「これはどの不満に効くのか」で切れます
2. **やらないことのリストが、やることのリストと同じくらい役に立ちました。** 個人開発は止める人がいないので、自分で線を引いておく必要があります
3. **実装が終わってからが本番でした。** ストアに出す作業はコードとまったく関係なく、しかも 3 週間かかりました。次に作るときは最初から見積もりに入れます

技術的な中身は[技術構成](/engineering/app/indie-app-technical-architecture/)に、実装で踏んだ罠は iOS 編（[SwiftUI と SwiftData](/engineering/app/ios-swiftui-swiftdata-pitfalls/) / [課金とストア連携](/engineering/app/ios-storekit-widget-pitfalls/)）と [Android 編](/engineering/app/android-compose-room-billing-pitfalls/)に分けて書きました。
